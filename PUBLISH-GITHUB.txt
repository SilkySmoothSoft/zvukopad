КАК ВЫЛОЖИТЬ ЗВУКОПАД НА GITHUB
================================

Этот файл и publish-github.bat выкладываются на GitHub вместе с исходниками - в них нет ничего личного.
Логин, токен и адрес в них НЕ хранятся: батник спрашивает их при запуске
или берёт из вашего внешнего батника (см. "БЕЗ ВОПРОСОВ").
Глобальные настройки git и переменные Windows не меняются.


ЧТО КУДА
--------
  Исходники (код)          -> сам репозиторий (publish-github.bat)
  Готовая программа (exe)  -> раздел Releases репозитория (вручную на сайте, 2 минуты)

exe в сам репозиторий класть не принято: каждая версия навсегда остаётся в истории git
и раздувает его. В Releases же к каждой версии прикрепляется zip, и пользователи
скачивают его по кнопке. Это стандартный способ.


ОДИН РАЗ: ПОДГОТОВКА
--------------------
1. Установите Git for Windows: https://git-scm.com/download/win
   (при установке все пункты можно оставить по умолчанию).

2. Создайте репозиторий: https://github.com/new
   - Repository name: например zvukopad
   - Private или Public. Начать можно с Private, а когда всё проверите - сделать открытым:
     репозиторий -> Settings -> General -> внизу Danger Zone -> Change visibility.
   - НЕ ставьте галочки "Add a README", ".gitignore", "license" - пусть будет пустой.

3. Создайте токен (вместо пароля для git):
   https://github.com/settings/personal-access-tokens/new   (Fine-grained token)
   - Token name: zvukopad
   - Resource owner: тот, кому принадлежит репозиторий (ваш аккаунт или ваша организация).
   - Expiration: на ваш выбор (например 90 дней - потом создадите новый)
   - Repository access: Only select repositories -> выберите zvukopad
   - Permissions -> Add permissions -> Contents -> уровень Read and write
     (Metadata: Read-only добавится сама).
   - Generate token, скопируйте его (показывается один раз).

4. Лицензия (нужна, если репозиторий будет открытым): положите в папку проекта файл LICENSE.
   Проще всего MIT: текст на https://choosealicense.com/licenses/mit/
   (замените год и имя). pack.bat подхватит его сам.


БЕЗ ВОПРОСОВ: ВНЕШНИЙ БАТНИК С ЛОГИНОМ И ТОКЕНОМ
------------------------------------------------
Чтобы не вводить адрес, логин и токен каждый раз, создайте батник ВНЕ папки проекта,
например рядом с ней (папка проекта Zvukopad, батник - в той же папке, где лежит Zvukopad):

    @echo off
    chcp 65001 >nul
    setlocal
    set "GHREPO=https://github.com/ВАШ_ЛОГИН/zvukopad"
    set "GHLOGIN=ВАШ_ЛОГИН"
    set "GHTOKEN=github_pat_..."
    call "%~dp0Zvukopad\publish-github.bat"

Запускайте его вместо publish-github.bat. Любую из трёх строк set можно убрать -
тогда батник спросит это значение сам.
Не кладите этот файл в папку проекта, в архивы и в общие облачные папки.


КАЖДЫЙ РАЗ: ВЫЛОЖИТЬ НОВУЮ ВЕРСИЮ
---------------------------------
1. Положите новые исходники в папку (можно удалить всё старое и распаковать заново -
   git-папка не нужна, батник сам скачивает репозиторий во временную папку).
   Версия меняется в Cargo.toml - см. README.md, раздел "Как поменять версию".
2. build.bat - соберите программу (нужно для zip с exe).
3. publish-github.bat (или ваш внешний батник). Если что-то не задано - ответьте на вопросы:
     Адрес репозитория: https://github.com/ВАШ_ЛОГИН/zvukopad
     Логин - имя пользователя GitHub, НЕ почта.
     Ветка (Enter = main), имя и почта автора (Enter = по умолчанию),
     описание изменений (Enter = "Версия X.Y.Z").
   Батник покажет список изменений и отправит их.
   Когда git спросит Password - вставьте ТОКЕН, не пароль от сайта.
   Символы при вводе не видны - это нормально. Вставка в консоли - правый клик мыши.
   Если откроется окно входа Git Credential Manager - закройте его, вводите токен в консоли.

Что попадает в репозиторий: то же, что pack.bat кладёт в dist\Zvukopad-src-ВЕРСИЯ
(app, crates, plugins, docs, locales, assets, tools, .cargo и файлы из корня:
Cargo.toml, Cargo.lock, README.md, SOURCES.md, LICENSE, build.bat, run.bat, pack.bat,
publish-github.bat, этот файл ...).
Не попадают: target, .toolchain, release, dist, логи и папка .github (её убирает publish-github.bat).
Файлы, которые вы удалили из исходников, удалятся и из репозитория.


КАЖДЫЙ РАЗ: ВЫЛОЖИТЬ EXE (RELEASES)
-----------------------------------
После publish-github.bat в папке dist лежит готовый архив:
    dist\Zvukopad-ВЕРСИЯ-win64.zip      (это и есть папка release\Zvukopad, упакованная)

Перед выкладкой можно проверить, что в exe нет вашего имени
(build.bat заменяет пути с компьютера на нейтральные):
    findstr /i /m /l "ваше_имя_в_windows" release\Zvukopad\zvukopad.exe
Если команда ничего не вывела - всё чисто.

1. Откройте https://github.com/ВАШ_ЛОГИН/zvukopad/releases/new
2. Choose a tag -> впишите v1.0.0 (номер версии) -> Create new tag.
3. Release title: Звукопад 1.0.0
4. Описание: скопируйте раздел этой версии из CHANGELOG.md. Можно добавить:
     Скачайте zip, распакуйте, запустите zvukopad.exe - устанавливать ничего не нужно.
     Если Windows покажет "Система Windows защитила ваш компьютер" -
     "Подробнее" -> "Выполнить в любом случае".
5. Перетащите zip в поле "Attach binaries". Архив с исходниками не нужен - GitHub добавит его сам.
6. Publish release.

Заменить zip в уже выложенном релизе: релиз -> Edit -> удалить старый файл,
перетащить новый -> Update release.

Совет: в описание релиза можно добавить контрольную сумму zip, чтобы люди могли проверить файл:
    certutil -hashfile dist\Zvukopad-1.0.0-win64.zip SHA256


НОВЫЙ КОМПЬЮТЕР
---------------
1. Скачайте исходники: на GitHub Code -> Download ZIP (или git clone).
2. build.bat - сам поставит Rust в папку проекта и соберёт программу.
3. Установите Git for Windows и создайте внешний батник с токеном (лучше новый токен).
Звуки и настройки программы в репозиторий не попадают:
    Документы\Zvukopad\Sounds\   и   %APPDATA%\Zvukopad\
Если они ценны - переносите их отдельно.


ЗАМЕТКИ
-------
- Сборка на GitHub (GitHub Actions) отключена: папка .github\workflows остаётся только у вас
  и не выкладывается. Включить: в publish-github.bat удалить строку, которая удаляет папку .github,
  и дать токену право Workflows: Read and write. Для открытых репозиториев сборка бесплатна,
  для приватных - в пределах бесплатных минут.
- Ошибка 403 "Write access to repository not granted" - у токена нет права Contents: Read and write,
  не выбран репозиторий или неверный Resource owner.
- Antivirus. Неподписанный exe иногда помечается антивирусами/SmartScreen. Это нормально для
  новых программ; со временем репутация файла растёт. Подпись сертификатом - платная.
- Если push пишет "rejected" - на GitHub есть изменения, которых нет у вас (например, правили
  README на сайте). Самое простое - не править файлы на сайте, только через этот батник.
- Токен истёк - создайте новый (шаг 3 подготовки), старый можно удалить на той же странице.
